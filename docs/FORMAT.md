# Формат конспекта `.bk`

Файл читается построчно. Комментарий: `--` до конца строки. Ключевые слова английские,
имена (теорем, теорий, меток) могут быть любыми в UTF-8. Комментарий в начале строки
попадает в документацию как текст, в нём можно писать LaTeX (`docs/DOCS.md`).

Короткий пример целиком:

```
import "00_prelude.bk"          -- схемы S1-S7 и теории в пространстве имён base
open base

in Logical
theorem C8 {A : rel} : A ⇒ A {
  A ⇒ (A ∨ A)                                  by S2 with A := A; B := A
  (A ∨ A) ⇒ A                                  by S1
  ((A ∨ A) ⇒ A) ⇒ ((A ⇒ (A ∨ A)) ⇒ (A ⇒ A))    by S4
  (A ⇒ (A ∨ A)) ⇒ (A ⇒ A)                      by mp 2 3
  A ⇒ A                                        by mp 1 ^
}
```

## Объявления

```
import "00_prelude.bk"           -- прелюдия: base.S1-S7, base.Logical, base.Quantified, base.Egalitarian
import "01_logic.bk"             -- другой файл (путь относительно текущего)
open base                        -- писать S1, Logical вместо base.S1, base.Logical

namespace ch1                    -- имена ниже получают приставку ch1.
  ...
end
open ch1                         -- короткие имена из ch1 видны без приставки
alias imp_refl := ch1.C8         -- второе имя того же объекта

sign ∈ [\in] : rel 2 infix       -- специальный знак: вид rel/term, вес, infix (только для веса 2)
sign m : term 2                  -- субстантивный знак веса 2: m(x, y) или (префиксно) m x y

abbrev ⊂ [\subset] (X Y : term) infix := (∀z)(z ∈ X ⇒ z ∈ Y)
abbrev ≠ (X Y : term) infix := ¬(X = Y)
abbrev Coll (R : rel 1) := (∃y)(∀x)(x ∈ y ⇔ R(x))   -- связывает букву: Coll_x(x ∈ a)
abbrev ∅ := τX((∀x)(x ∉ X))                          -- без параметров

scheme S5 {R : rel 1} {T : term} : R(T) ⇒ (∃x) R(x)   -- схема-образец

theory Sets extends Egalitarian {
  signs ∈
  schemes S8
  axiom A1 : (∀x)(∀y)(...)       -- буквы в явных аксиомах это константы
}
theory Logical { schemes S1 S2 S3 S4 }   -- можно в одну строку

in Sets                          -- теория по умолчанию для следующих теорем

#set infix | #set prefix         -- запись формул до конца файла (см. ниже)
#show x ⊂ y                      -- напечатать формулу (в обеих записях)
#signs (∃x)(x ∈ y)               -- нарисовать знакосочетание со связями
#print C8                        -- напечатать формулировку теоремы
#expand C8                       -- раскрыть до S1-S7 и C1, проверить, сказать размер
#unfold C8                       -- то же и выписать все строки
#formation (∃x)(x = y)           -- формативная конструкция (§ 1, n° 4) с пометками а)-д)
#log                             -- где мы: namespace, open, теория, запись, сколько доказано
#format prefix | #format infix   -- запись только для следующей теоремы

model M : G -> H with e := c; s := c {   -- модель (C5), см. ниже
  G1 by cc
}
transfer g_ex via M [as имя]     -- перенести теорему моделью
```

`namespace`, `open`, `in` и `#set` действуют до конца файла; импорт их не меняет.

## Как работает import

`import "файл.bk"` не вставляет текст. Импортированный файл проверяется отдельно, в
своём начальном состоянии (без чужих `namespace`, `open`, `in`, `#set`), и всё, что в нём
объявлено и доказано, добавляется в общий конспект под полными именами (`ch1.C8`,
`base.S1`). Потом проверка текущего файла продолжается с того же места, с его собственными
`open` и `in`. Поэтому каждый файл сам пишет `open base`, если хочет короткие имена.

* Каждый файл проверяется один раз: повторный импорт (в том числе через другой файл)
  пропускается. Имена объявлять дважды нельзя ("имя ... уже занято").
* Знаки и сокращения (`sign`, `abbrev`) это запись формул, они общие для всего
  конспекта и видны после импорта без приставок.
* Пути считаются от папки текущего файла.

## Имена

Имя ищется так: сначала в текущем пространстве и объемлющих (`a.b.x`, `a.x`, `x`), затем
в открытых через `open`. Если в открытых нашлось два разных `x`, это ошибка: пишите полное
имя. `alias` не создаёт нового объекта, поэтому `C8` и `imp_refl` никогда не конфликтуют.
Знаки и сокращения (то, как пишутся формулы) общие для всех пространств.

## Метапеременные

| запись            | смысл у Бурбаки                         | внутри                    |
|-------------------|-----------------------------------------|---------------------------|
| `{A B : rel}`     | A, B произвольные соотношения           | знаки веса 0              |
| `{T : term}`      | T произвольный терм                     | субстантивный знак веса 0 |
| `{R : rel 1}`     | R{x}, соотношение с выделенной буквой   | знак веса 1, пишется R(x) |
| `{R : rel 2}`     | R{x, y}                                 | знак веса 2               |

Метапеременная A веса 0 не зависит ни от какой буквы: `(∀x)A` есть просто `¬¬A`.
Если нужна зависимость от x, объявляйте `{R : rel 1}` и пишите `R(x)`.

## Теорема

```
theorem ИМЯ {метапеременные} (h1 : гипотеза) ... : утверждение [in Теория] {
  формула   by обоснование
  формула   by обоснование
  ...
}
theorem ИМЯ ... : утверждение by обоснование      -- в одну строку
```

* Строки нумеруются сами: 1, 2, ... в каждом блоке. Номер можно написать (`3. формула by ...`),
  тогда он должен совпадать с настоящим.
* Метка-имя: `h. формула by ...`, потом ссылаться на `h`.
* `^` предыдущая строка, `^^` две назад. На первой строке блока `^` это гипотеза блока.
  Внутри блока `^` не выходит за его начало; на строки снаружи ссылаются метками.
* Вместо формулы `_`: её выведет проверка (для схем, теорем, mp, gen, subst; для `taut`
  формулу надо написать).
  `_` в последней строке значит само утверждение теоремы.
* Последняя строка должна совпадать с утверждением. Гипотезы теоремы ведут себя как явные
  аксиомы (их буквы константы).

## Обоснования

Общая форма: `by ПРАВИЛО ссылки... [with параметры]`, параметры через `;`.

| запись                                   | что это                                                  |
|------------------------------------------|----------------------------------------------------------|
| `by S4 with A := P ∨ P; B := P; C := ¬P` | схема с подстановкой                                      |
| `by S4`                                  | схема, подстановка восстанавливается по строке            |
| `by S5 with R(x) := x ∈ y; T := z`       | метапеременной веса 1 подстановка пишется с буквой        |
| `by S5`                                  | R(x) тоже восстанавливается, если строка это позволяет    |
| `by C6 1 ^`, `by C6 1 ^ with A := ...`   | доказанная теорема; ссылки это строки с её гипотезами     |
| `by mp 2 3` (или `C1`)                   | силлогизм: из S и S ⇒ R получить R (порядок любой)        |
| `by h`, `by 3`, `by ^`                   | повторить гипотезу или строку                             |
| `by axiom`, `by axiom A1`                | явная аксиома теории                                      |
| `by assume h {` ... `}` (или `C14`)      | строка A ⇒ B, в блоке доказать B в 𝒯 + A                  |
| `by contra g {` ... `}` (или `C15`)      | строка A, в блоке 𝒯 + (не A) найти B и не B               |
| `by gen 3 with x` (или `C27`)            | обобщение: (∀x)R из R, x не константа                     |
| `by subst 3 with x := T` (или `C3`)      | подстановка в букву, x не константа                       |
| `by taut`                                | упр. 7: тавтология (проверка таблицей истинности)         |
| `by taut a b 3`                          | строка следует из строк a, b, 3 по тавтологии: (a и b и 3) ⇒ строка |
| `by chain p q r`                         | цепочка равенств T = U, U = V, ... (в любом порядке и направлении) даёт T = W |
| `by sorry`                               | пропуск, теорема помечается                               |

Как восстанавливается подстановка. Метапеременная веса 0 (A) находится сопоставлением
образца со строкой. Метапеременная R веса k находится, если где-то в образце она стоит
как R(x₁, ..., xₖ) с различными связанными буквами (образец Миллера): так в (∃x)R(x)
тело R видно сразу. Вхождения вида R(T) проверяются после этого. Если R нигде так не
стоит (например, в S6: T = U ⇒ (R(T) ⇔ R(U))), подстановку надо написать.
Найденная подстановка всегда проверяется: строка должна совпасть буквально.

## Новые правила это теоремы

Почти любое "правило рассуждения" записывается теоремой с гипотезами, и язык для этого
менять не нужно. Пример: метод вспомогательной константы C19 (`ch1.C19` и `ch1.obtain` в
`05_quant.bk`). "Пусть x такой предмет, что A(x)" это блок `assume`, затем обобщение:

```
A(x) ⇒ B           by assume h {
  ...                                -- внутри блока x вспомогательная константа
  B                  by ...
}
(∀x)(A(x) ⇒ B)     by gen ^ with x  -- проверяется, что x не константа теории
B                  by obtain e ^     -- e: строка (∃x)A(x); или by C19 t ^, t: строка A(T)
```

Условие "x не встречается в B" выполняется само: B в теореме это метапеременная веса 0,
а после `gen` все вхождения x связаны, так что если бы B содержало x, строка не подошла бы
под образец `(∀x)(A(x) ⇒ B)`.

Отдельное правило языка нужно, только если рассуждение меняет теорию так, как теоремой не
сказать (сами `assume`, `contra`, `gen`, `subst`, `taut`).

## Сокращения со связанной буквой

Параметр сокращения веса k (`(R : rel 1)`, `(R : rel 2)`) это соотношение с выделенными
буквами, как R{x} у Бурбаки. Такое сокращение связывает буквы, их пишут после `_`:

```
abbrev Coll (R : rel 1) := (∃y)(∀x)(x ∈ y ⇔ R(x))
abbrev ExA (A R : rel 1) := (∃x)(A(x) ∧ R(x))     -- типовой квантор (∃_A x)R
abbrev Two (R : rel 2) := (∀x)(∀y)(R(x, y) ⇒ R(y, x))

Coll_x(x ∈ a)            ExA_x(x ∈ X, x = y)            Two_{x,y}(x ∈ y)
Coll_x ∈ x a             -- то же в префиксной записи
```

Слово `nofold` после параметров (`abbrev ExA (A R : rel 1) nofold := ...`) запрещает печати
сворачивать знакосочетание в это сокращение (если сокращение слишком общее и мешает читать).

Связываемых букв столько, каков наибольший вес параметра; параметр веса k выделяет первые
k из них, параметры веса 0 не выделяют ничего (буква x в них остаётся свободной). Связанная
буква ничего не значит: `Coll_x(x ∈ a)` и `Coll_z(z ∈ a)` одно и то же знакосочетание.
Печать узнаёт такие знакосочетания и сворачивает их обратно (букву берёт свежую).

## Модели (C5)

```
model M : Source -> Target with a := T; b := U {
  A1 by обоснование          -- образ аксиомы A1 теории Source есть теорема Target
  A2 by обоснование
}
transfer thm via M as thm2   -- образ теоремы Source есть теорема Target (по C5)
```

* Знаки и схемы Source должны быть в Target. Вместо букв a, b подставляются термы T, U
  теории Target (одновременно; термы не должны содержать заменяемых букв).
* Для каждой явной аксиомы Source нужна строка `ИМЯ by ...`: её образ проверяется в Target
  как обычная строка доказательства. Длинное доказательство оформляется отдельной теоремой.
* `transfer` создаёт теорему Target (метапеременные и гипотезы переносятся образом).
  Без `as` новое имя `M.thm`.
* `#expand` перенесённой теоремы строит доказательство так, как в доказательстве C5:
  подстановки C2 во всё доказательство источника, затем каждая аксиома заменяется
  доказательством её образа (C4).

## Запись формул: одна на файл

Чтобы запись читалась однозначно, в каждом месте файла действует одна запись.

**Инфиксная** (`#set infix`, по умолчанию): бинарные связки и инфиксные знаки между
операндами, остальные знаки как вызов, `¬`, кванторы и τ впереди.

```
x ∈ y ⇒ (∀z)(z ∈ x ∨ ¬(z = y))      m(x, y) ∈ x      R(x)      τx(x ∈ y)
```

Приоритеты: `⇔` < `⇒` (вправо) < `∨` (влево) < `∧` < `¬`, кванторы, знаки.
Квантор связывает сильно: `(∃x)(A ⇒ B)` требует скобок, а `(∀x)R(x) ⇒ S` значит `((∀x)R(x)) ⇒ S`.

**Префиксная** (`#set prefix`, польская запись Бурбаки): всё впереди, скобки не нужны
(но можно ставить для группировки). Так записываются и знаки любого веса.

```
⇒ ∈ x y ∀z ∨ ∈ z x ¬ = z y      ∈ m x y x      R x      τx ∈ x y
or A or B C   это   ∨ A (∨ B C)
```

Использовать чужую форму нельзя: в инфиксной `∨ A B` и в префиксной `A ∨ B` дают ошибку.

## Набор значков

| значок | набор                                           |
|--------|-------------------------------------------------|
| `¬`    | `~` `not` `\neg` `\lnot` `\not`                  |
| `∨`    | `or` `\lor` `\vee` `\or`                        |
| `∧`    | `and` `\land` `\wedge` `\and`                   |
| `⇒`    | `=>` `->` `implies` `\to` `\imp` `\Rightarrow`   |
| `⇔`    | `<=>` `<->` `iff` `\iff` `\Leftrightarrow`       |
| `∃` `∀` `τ` | `exists` `forall` `tau`, `\exists` `\forall` `\tau` |

ASCII-замен `\/`, `/\`, `&` нет: они путаются с a/b, a\b. Слова (`or`, `and`, ...) это
один значок, а не буквы. Своим знакам можно дать имена для
набора: `sign ∈ [\in] : rel 2 infix`. Слова `in`, `by`, `with` зарезервированы.

## Как это проверяется

* Строка со схемой: подставить в образец и сравнить знакосочетания (после раскрытия всех
  сокращений). Строка с теоремой: подставить в её формулировку. Время линейно по тексту.
* `#expand` строит настоящее доказательство из явных аксиом, схем и C1 (теорема
  подставляется в своё раскрытое доказательство, C14 перестраивается как у Бурбаки) и
  проверяет его отдельным проверяльщиком. Это медленнее и делается только по запросу.
  Теорема помнит своё пространство имён и запись, так что раскрытие понимает её так же.
